**Optimize** hands the workflow's open values to an optimizer. Each trial, the optimizer suggests
values, the workflow runs with them, and what it measured is reported back.

<Shot name="run-optimize" alt="The Optimize tab: engine, budget and batch size, and the search space" />

<Aside type="note" title="An optimizer must be installed on the deck">
The engine list shows what the deck has: **Ax**, **BayBE**, **NIMO**. In the desktop app, add one
under the deck's **Settings → Optimizers**. A backend that is installed but missing from the list
failed to load, and the deck's log says why at startup.
</Aside>

Each open variable in the search space is one of:

| Kind | Meaning |
|---|---|
| **Range** | `min` to `max`. A step (`by`) makes it a grid. |
| **Choice** | a list of values |
| **Substance** | a SMILES per name (BayBE with its chemistry extra) |
| **Fixed** | one value for the whole run; the variable leaves the search |
| **Per-iteration** (the box on the right) | a value you give for each trial, not searched: a vial position |

## Objectives and existing data

<Shot name="run-optimize-objectives" alt="Objectives, stopping rules, constraints and existing data" />

- **Don't optimize** keeps an output out of the search: it is still measured and kept in its own
  column of every trial, for a later step to read or for the record. At least one output must be
  optimized.
- **Stop when no objective has improved for N iterations** never counts the random start.
- **Pause and ask me when a trial gives no result** asks instead of leaving such a trial out.
- **Constraints** are relations the suggestions must satisfy (`catalyst_ml + ligand_ml <= 0.6`),
  checked before the run is accepted.
- **Existing data** takes earlier runs from Data History whose search space and objectives match,
  or a CSV with those columns.

## What the three backends do differently

They count the random start differently, treat a failed trial differently, and use existing data
differently. [How the optimizers behave](/reference/optimizers/) has the table. In short:

- A trial whose objective came back missing is left out of the model and still counts towards the
  budget.
- The optimizer failing to suggest, or refusing a round's results, pauses the run and waits for
  you, like a failed step.
- NIMO takes only lists (a range with a step, or a choice) and does not use existing data.

## Suggestions without running

**Suggest only** opens a *campaign*: the optimizer suggests the next trials, you run them however
you like and type the results back in, and it suggests again. A campaign survives a restart.

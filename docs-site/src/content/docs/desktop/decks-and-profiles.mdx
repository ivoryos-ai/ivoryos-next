## A deck's page in the app

<Shot name="launcher-deck" alt="A deck profile's page: Start, Restart and Open, its tabs, and its instruments" />

- **Start** checks the Python environment (the first time it downloads Python and installs
  IvoryOS), checks the port is free, starts the process and waits until it answers. The deck then
  opens by itself, unless you have moved on to something else meanwhile.
- A deck whose instruments did not all load opens on its Instruments tab, with the failures in red.
- **Stop** asks the process to shut down and forces it after a few seconds.
- **Restart** is always a new process: it re-reads the deck file, re-imports the drivers and
  reconnects every instrument. With a run under way the app asks first, naming the run:
  restarting ends it where it is, without its cleanup. Restart on the deck's Instruments page does
  the same through the deck itself, and is refused while a run is going unless you confirm.

Anyone who can reach the port can drive the instruments, so turn **Reachable from other
computers** off for a deck only this computer should open. Others open it at
`http://<this computer's address>:<port>`.

## A deck's instruments, plugins and packages

A deck profile's **Instruments** tab lists what is on the deck. Each instrument and each plugin has
an **on** switch, which keeps it in the deck file without loading it (an unplugged device, a plugin
you do not need today), and **Remove**.

**Nothing restarts a running deck for you.** Switching something on or off, editing or removing an
instrument, adding from the Hub, saving a setting or the script: each is saved at once, and the
deck goes on running what it started with, so a run under way is not interrupted and the deck
stays on Cloud. Whenever what is saved differs from what the deck is running, its header says
**Not applied yet: restart to apply** (hover it for what changed), the rows that differ say so
(*still loaded until restart*, *loads at restart*), and **Restart** is yours to press when nothing
is running. Undo the change and the notice goes away.

Installing never stops a running deck either. An install that only adds packages goes in while
the deck runs and waits for your restart. One that would replace a package already installed
(every package update, some optimizer changes) asks you to stop the deck first, because a running
Python holds those files open. And nothing is installed while a run is under way.

Under them, **Driver packages** lists the Python packages the deck asks for, each with the version
installed and what on the deck uses it. All decks share one Python environment, so **nothing is
ever uninstalled**; the list only says what this deck needs:

- Removing an instrument or plugin also takes off the list the packages only it needed (worked out
  from what the installed packages depend on). They stay installed.
- A package nothing on the deck uses (left from before this existed, or added by hand) says so.
  Remove it, or **Remove unused** for all of them.
- **Check for updates** looks for the newest version of each that still installs with the rest of
  the deck's packages. **Update** installs it and pins the deck to it (stop the deck first: it is
  not stopped for you); if it cannot be installed, the deck is left as it was. Optimizers are
  chosen in the deck's Settings instead, from versions tested together, and a private repository
  moves to a newer commit by importing it again.

### When packages clash

Every install is first checked against what the other decks in the shared Python have installed,
and against what IvoryOS itself needs. When they do not fit, nothing is installed, and a dialog
says what uv found:

- **Another deck's packages** need other versions: **Give it its own Python** sets up an
  environment for this deck alone, in seconds, and installs there. Both decks then run. The deck's
  **Settings → Python** shows which one it uses, and moves it back when its packages fit again.
- **The deck's own packages**, or **IvoryOS itself**, need other versions: one Python holds one
  version of each package, so no environment helps. Put one of the drivers on another deck, or
  change a version.

**Copy** copies the problem, every deck's package list and the rules for trying fixes safely,
written for Claude Code or another coding agent on this computer. If it changes the deck's
package list, Start installs it, checked the same way.

## A script's instruments

Every object a script makes at the top of the file is an instrument, except what clearly is not:
a pandas table, a numpy array, a plot, a web app, Python's own objects (a `Path`, a lock, a
logger), and objects with nothing to call. A script profile's **Overview** lists what the running
script put on the deck and, folded under it, what it left out, each with an **on** switch. A switch
is saved with the profile and applies when you restart the script. Switched off, an object is only
kept off the deck: the script still makes it, so a port it opened stays open. The choice is the
app's: the same script run from a terminal or PyCharm uses `exclude_names` and `include_names` in
its `run()` call instead, and an object those name is shown as "set in the script", with no switch.

## Script profile settings

<Shot name="launcher-script-settings" alt="A script profile's Configuration tab with Advanced open" />

A script profile needs its Python file and nothing else. Everything under **Advanced** can stay
empty.

| Setting | Empty means | Set it when |
|---|---|---|
| **Python interpreter** | the app's own Python, which has IvoryOS and every driver installed from the Hub | the script needs a project's packages: choose that project's `.venv/bin/python` (`.venv\Scripts\python.exe` on Windows). The line under the field says whether IvoryOS is installed there, and offers to install it. |
| **Working folder** | the script's own folder | the script expects to run somewhere else |
| **Environment variables** | none | something should change without editing the script, usually a port |

Imports are found in the script's folder, the working folder, and the project above the script
(the folders holding `pyproject.toml`, `setup.py`, `requirements.txt`, `.git` or `.idea`, and their
`src/`), as PyCharm does. A `PYTHONPATH` variable adds a folder.

```python
import os
pump_1 = SyringePump(port=os.environ.get("PUMP_PORT", "COM3"))   # COM3 unless set
```

Add `PUMP_PORT = COM4` and restart. The same script can have two profiles, *Bench A* with COM3 and
*Bench B* with COM4. The app also sets `IVORYOS_PORT`, `IVORYOS_HOST` and `IVORYOS_DATA_DIR`, which
`ivoryos_edge.run(__name__)` reads: that is how a script lands on its profile's port unchanged.

## Where things are on disk

| Path (macOS: `~/Library/Application Support/IvoryOS/`; Windows: `%APPDATA%\IvoryOS`; Linux: `~/.config/IvoryOS`) | What |
|---|---|
| `profiles.json` | your profiles and the app's settings |
| `profiles/<id>/deck.json` | a deck profile's instruments (Settings → Show deck file) |
| `profiles/<id>/data/` | that deck's runs, workflows, safety configuration and Cloud pairing |
| `runtime/venv/` | the Python environment the decks share, managed by uv |
| `runtime/envs/<id>/` | a deck's own Python environment, when it has one |
| `logs/<id>.log` | each profile's output |

Deleting `runtime/` is safe: it is rebuilt on the next start, decks' own environments included. Deleting `profiles/<id>/data/`
deletes that deck's run history.

The Instruments page is the deck as the drivers describe it: one entry per instrument, one form
per method. Use it to test a new driver, to drive something by hand between runs, and to see what
did not load.

<Shot name="instruments" alt="The Instruments page with Pump 1 selected and a form for each of its methods" />

- Required fields are marked `*`. Dropdowns, True/False and nested forms follow the driver's type
  hints.
- The search box at the top right filters methods by name.

## Run a method by hand

<Shot name="instruments-execute" alt="The action log after running a method by hand" />

<Aside type="caution" title="While a run is going">
**Execute** bypasses the queue and drives the hardware at once, even in the middle of a run. The
page asks you to confirm when a run is active. Pause the run first.
</Aside>

## Set a limit from here

The shield beside a field opens the same editor the [Safety](/guide/safety/) page uses, for that
one field: a lowest and highest value, a list of allowed values, a tray, or just a unit. Once saved
it is checked before every run and every call.

## Not loaded

An instrument whose driver failed to import, whose constructor raised, or whose setup call failed
is listed under **Not loaded** with the full error. The rest of the deck runs without it. Fix the
cause (plug it in, correct the port, install the package) and **Restart**.

## Restart and deck versions

- **Restart** re-reads the deck file, re-imports the drivers (so an edited driver takes effect) and
  reconnects every instrument. It is refused during a run unless you confirm.
- **deck v*N*** opens the history: every time the instruments or their methods changed, with what
  was added, removed or retyped. Every run and every saved workflow version is stamped with the
  deck version it belongs to.

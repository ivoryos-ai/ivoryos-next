## In a browser

The gear at the end of the navigation opens **Settings**. All three are kept in that browser.

<Shot name="settings" alt="The deck's Settings page in a browser: theme, navigation, notifications" />

The page also asks once, the first time a run is under way, whether it may notify you.

## In the desktop app

The deck's gear is hidden: theme and layout follow the app (**Settings** in the launcher), and the
app does the notifying for every running deck, whether or not its tab is open.

| Group | Announces | Default |
|---|---|---|
| **Needs you** | a step waiting for input, a failed step, a deck that stopped unexpectedly | on, with sound |
| **When a run ends** | a run that finished (only runs longer than 5 min by default), or one that stopped or failed | finished on, stopped off |
| **Heads up** | a deck you started is ready or could not start; an install finished or failed | on, only while you are in another app |

- Each deck can be muted.
- Nothing about a deck is announced while its tab is the one you are looking at.
- If the system refuses the app's notifications, Settings says so and offers a test and a link to
  the system's notification settings. The Dock bounce or flashing taskbar button works regardless.

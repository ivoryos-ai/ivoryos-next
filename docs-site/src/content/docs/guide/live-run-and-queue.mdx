A run is watched where it was started. The chip at the bottom of the Run page reads **Idle**,
**N queued** or **Queue paused**. When a run starts it widens into the **run bar**, and shrinks
back when the run is over. On other pages a small floating card shows the same thing.

<Shot name="live-run" alt="The run bar during a run, with its controls" />

**Pause** waits for the step under way to finish; the same button resumes.

| Stop | What happens |
|---|---|
| **Stop after this iteration** (the flag) | Finishes the sample, batch or trial it is on, then stops. It asks whether to run cleanup and whether queued runs go on. |
| **Stop now** (the square) | Stops at once. Cleanup does not run, and the queue is held until you resume it. |

## The steps

<Shot name="live-run-steps" alt="The run bar opened to show every step" />

The list follows the running step unless you scroll it yourself. Drag the bar along its top to make the list taller;
double-click it to reset.

## When the run needs you

**A step failed.** Nothing is retried or skipped by itself. The run and the queue wait, and this
appears on whichever page you are on:

<Shot name="run-decision" alt="A failed step waiting for a decision: change and retry, retry, skip, or stop" />

Plain **Stop run** leaves cleanup out because a failure may have left the deck in a state cleanup
should not walk into. The error and what you chose stay with the run's record.

**A User input step.**

<Shot name="user-input-prompt" alt="A User input step's prompt" />

A User input step with no variable name is a plain pause: the message and **Continue**.

**The optimizer** cannot suggest, or refuses a round's results: the same kind of pop-up, with its
own choices. See [Optimize](/run/optimize/).

<Aside type="tip" title="Away from the screen">
The desktop app turns these moments into system notifications, with sound for what needs you. In a
browser the page asks once whether it may notify you. See
[Settings and notifications](/guide/settings-and-notifications/).
</Aside>

## The queue

Runs go one at a time. Starting a run while another is going (**Add to Queue**) puts it behind.

<Shot name="queue-drawer" alt="The queue drawer: the run under way and what waits behind it" />

- A queued run's size is in its own unit: steps and rows, or iterations for an optimization.
- Changing a queued run's values opens its Run page again; **Save changes** puts it back in place.
- **Resume queue** appears whenever the queue is held: after **Stop now**, after a failed run was
  stopped, or after a graceful stop told to hold. A new run you start while nothing else waits
  starts anyway.
